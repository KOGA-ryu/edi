## 2. The pipeline — where each seam stands

- **Seam A (Blender → asset): engine solid, NO UI home.** The recipe engine parses
  TOML ops → binds/resolves → compiles deterministic bpy; `ProcessRunStore` spawns
  headless Blender; the render PNG shows in the "Render" preview panel (Blender
  workspace, `B` in the left rail). Missing: a *lab workspace* fusing the drafting
  grid (it supplies parameters) + editor + ASCII proof + render. Fires only via CLI/
  Build hook today.
- **Seam B (asset → dungeon): ✅ REPAIRED this session.** A `DraftingBlock` carries
  `assetRef` (the Blender asset it depicts); `placeBlockInstance` stamps
  `BlockPlacementMetadata` (blockId + asset snapshot + a shared `instanceId`) onto
  every flattened object, so a placement is traceable. *Real asset values stay empty
  until Seam A's lab produces asset ids to link (P2).*
- **Seam C (dungeon → engine): ✅ FLOWS this session.** Rooms now live in the document
  (`DraftingMapRoom` vector), the authoring scale is stored (`canvasPerAuthoredUnit`),
  and a document-based `exportMapToToon` emits rooms/plugs/connections **+ a
  `blocks[]{room,asset,origin,scale,rotation}` section** in authored feet.
  `--export-map` reads a saved `.edidraw` to carry the placed blocks. *Placement is
  translate-only (scale/rotation = 1/0 until the deferred `transformGeometry`).*

**Net:** the data path is whole end to end — `Blender asset → block → stamped dungeon
→ engine`. What fills it (real asset ids, a lab to make them) is P2.

## 5. Cadence & conventions (decided this session)

- **Light cadence is the default.** Plan → build → test → commit per slice, inline.
  Run a design/critique workflow at *phase starts* and an adversarial/skeptic pass at
  *risky joints* (new seams, new formats). The old heavyweight bucket/external-builder/
  mutation protocol (the `ui-restoration` R-track) is retired — it doesn't scale to the
  remaining ~70%.
- **The green gate, every slice:** `cmake --build build && ctest --test-dir build`
  fully green, plus the no-JSON/no-qml scan, before each commit. (It earns its keep —
  it caught a latent dangling-ref UB this session.)
- **Persistence pattern for new document data:** mirror plugs/connections/blocks/rooms
  — a document-level vector + free-function ops + a `DraftingCommand` arm + **additive,
  tolerant MessagePack (missing key ⇒ default, NO document-version bump)**. This is the
  worn groove; reuse it.
- **The user owns the look.** Flag visible UI changes; keep heavy polish out unless
  asked (re-bless `tests/golden/*.png` via `EDI_BLESS_GOLDEN=1 ./build/edi_shell_window_tests`
  after an intended look change).

## 6. Build · run · view · export

```
cmake --build build && ctest --test-dir build --output-on-failure   # build + test
./build/edi                                                         # the GUI app
./build/edi --map-file tests/data/dungeon.map.toml                  # open a dungeon (window)
QT_QPA_PLATFORM=offscreen ./build/edi --map-file <map>.map.toml --snapshot /tmp/x.png   # render to PNG
QT_QPA_PLATFORM=offscreen ./build/edi --map-file <map>.map.toml --export-map out.toon   # export (.map.toml = feet topology)
QT_QPA_PLATFORM=offscreen ./build/edi --map-file <saved>.edidraw --export-map out.toon  # export WITH placed blocks
```
The reference dungeon: `tests/data/dungeon.map.toml` (10 rooms + a 3-way junction +
secret doors + 12 corridors). Corpus: `tests/data/maps/{minimal,hallway,loop,hub,secrets}.map.toml`.

## 7. Open threads & gotchas

- **Push state:** `master` is synced with `origin` — nothing local-only.
- **The Blocks palette** floats over the canvas top-left, minimal/unstyled — the user
  is set to restyle it (placement + look). Code: `DraftingFeaturePanels.cpp` `buildPalettes`
  (`block_palette`) + `refreshBlockPalette`.
- **assetRef linking from the UI is not wired** — blocks define from drawn geometry
  today; linking to a real Blender asset waits on P2's lab.
- **Test gotchas (CLAUDE.md):** `rebuildGeometryEditor` retires spins with
  `deleteLater()` — flush `QEvent::DeferredDelete` before widget lookups. Hold
  document data by VALUE, not a reference, across an undo/redo (a `DraftingBlock&`
  into `document.blocks` dangles after undo repopulates the vector — bit us this session).
- **Stale-lock recovery:** if `.git/index.lock`/`HEAD.lock` blocks a commit, confirm
  it's a zero-byte stale file (only `fsmonitor--daemon` git running) before removing.
